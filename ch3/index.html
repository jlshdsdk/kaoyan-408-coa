第3章 存储系统

本章是历年真题的重灾区：Cache 与虚拟存储器的考点容易出综合题，存储器的格式与扩展（芯片选择、连接方式）、交叉存取、Cache 的相关计算与替换算法、虚拟存储器与 TLB 则是选择题的高频产区。建议在掌握基本原理的基础上，多结合题目反复练习，尤其要在掌握 TLB 基本原理的前提下多做「地址翻译与 Cache 映射」的综合训练。

408考纲要求
  • （一）存储器的分类
  • （二）层次化存储器的基本结构
  • （三）半导体随机存储器：SRAM、DRAM、Flash 存储器。
  • （四）主存储器：DRAM 芯片和内存条、多模块存储器、主存储器和 CPU 之间的连接。
  • （五）外部存储器：磁盘存储器、固态硬盘（SSD）。
  • （六）高速缓冲存储器（Cache）：Cache 的基本原理；Cache 和主存之间的映射方式；Cache 中主存块的替换算法；Cache 写策略。
  • （七）虚拟存储器：虚拟存储器的基本概念；页式虚拟存储器——基本原理、页表、地址转换、TLB（快表）；段式虚拟存储器的基本原理；段页式虚拟存储器的基本原理。

  2. 影响 Cache 性能的因素有哪些？
  3. 虚拟存储系统的页面是设置得大一些好还是设置得小一些好？

按元件/存取方式/可改变性/可保存性四种分类，主存的组成与 MAR/MDR，层次化结构中 Cache-主存、主存-辅存两个层级的分工，以及存取时间、存取周期、带宽三大指标。

SRAM 触发器 vs DRAM 电容（刷新、地址复用），ROM 家族与 Flash，多模块存储器的连续编址与低位交叉流水存取（m=T/r、t=T+(m−1)r）。

3.4 外部存储器

页式（页表、地址变换、TLB）、段式、段页式三种机制，TLB/Cache/页表的缺失组合分析，虚拟存储器与 Cache 的异同。

本章小结

下表整理自教材本章小结，回答开篇的三个思考题。

问题结论要点
存储器系统为何要分这些层次？计算机如何管理这些层次？ 存储系统采用多级层次结构，旨在兼顾存储速度、存储容量与单位成本：Cache-主存层主要用于加速 CPU 访存，使平均访问速度接近 Cache，而寻址空间和单位价格接近主存；主存-辅存层主要用于扩展可用存储容量，使程序员看到的地址空间和单位价格接近辅存，而访问速度接近主存。Cache 与主存之间的信息调度由硬件自动完成，对程序员透明；主存与辅存之间的信息调度通过虚拟存储技术实现，由软件与硬件共同完成——程序员使用远大于物理内存的虚拟地址空间编程，程序执行时由硬件和操作系统协作完成虚拟地址到物理地址的转换。
影响 Cache 性能的因素有哪些？ Cache 系统的性能主要由命中率决定，命中率又受多种因素影响：① 映射方式：全相联命中率最高，直接映射最低，组相联介于两者之间；② Cache 容量：容量越大命中率越高，但提升速度会放缓；③ 块大小（Cache 行大小）：块过小难以利用空间局部性，过大则可能降低有效容量并增加缺失损失，须适当权衡。此外，Cache 数量（单级/多级）、指令与数据 Cache 是否分离、以及主存-总线-Cache-CPU 的架构等，也会显著影响 Cache 的整体性能。
虚拟存储系统的页面是设置得大一些好还是小一些好？ 页面大小应适中，过大或过小都带来问题。页面过小：页表项数量剧增，导致页表庞大，同时难以有效利用空间局部性，降低命中率；页面过大：虽可减小页表规模，但会增加页内碎片、浪费内存空间，且页面调入/调出时的传输开销更大，延长缺页处理时间。因此实际系统通常选择 4KB～几 MB 的页面大小，在页表开销、局部性利用与 I/O 效率之间取得平衡。

常见问题和易混淆知识点

问题 1Cache 行的大小和命中率之间有什么关系？

当 Cache 行较大时，能更好地利用空间局部性，将更多的相邻数据一次性调入 Cache，从而提高命中率。但行长不宜过大，主要原因有两个：① 行长过大会增加缺失损失，即未命中时需从主存读取更多数据，传输时间更长；② 在 Cache 总容量固定的情况下，行长增大会导致行数减少，降低地址映射的灵活性，反而可能降低命中率。反之，行长过小会降低空间利用效率，且难以有效利用空间局部性，命中率通常偏低。

易混「行大 → 命中率高」不是无条件成立：命中率先随行大而升（空间局部性），后因行数减少、缺失损失增大而受影响——要答出「适当权衡」这层意思。

问题 2发生取指令 Cache 缺失时的处理步骤是什么？

当发生取指令 Cache 缺失时，系统按以下步骤处理：

  1. 保持程序计数器（PC）不变，确保缺失处理完成后能重新获取同一条指令；
  2. 根据 PC 指向的地址，从主存读取该指令；
  3. 将该指令所在主存块调入 Cache，并更新对应 Cache 行的有效位和标记位；
  4. 重新从 Cache 中取指并继续执行。
