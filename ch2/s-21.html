2.1 数制与编码

这一节解决「数在机器里怎么写」的问题：先规定进位计数制并把各种转换练熟，再用原码、反码、补码、移码四种编码把定点数装进固定字长，最后落到 C 语言整数类型在真实编译器里的截断与扩展行为。本节是选择题的高频产区：进制转换、补码的表示范围、C 语言类型转换的位模式都要做到又快又准。

2.1.1进位计数制及其相互转换

1. 为什么计算机用二进制

计算机系统内部的所有信息，均采用二进制进行编码。原因有三：

  1. 二进制只有两个状态，只需使用具有两种稳定物理状态的器件即可表示一位，硬件实现成本低，可用高低电平稳定表示 0 和 1；
  2. 二进制的 1 和 0 恰好对应逻辑值「真」与「假」，为计算机实现逻辑运算和程序中的条件判断提供了直接支持；
  3. 二进制的运算规则极为简单，可通过基本的逻辑门电路高效实现各类算术与逻辑操作。
考点采用二进制编码的原因（2019 真题）。三条原因要能完整背出：物理上两种稳定状态、逻辑上对应真假、运算规则简单易于门电路实现。

2. 进位计数制的要素

常用的进位计数制包括十进制、二进制、八进制和十六进制。基数指每个数位所能使用的不同数码的个数（如十进制的基数为 10，数码为 0～9）；位权是每一位「逢 r 进一」的尺度，第 \(i\) 位的位权为 \(r^i\)。一个 \(r\) 进制数 \(K_n K_{n-1}\cdots K_1 K_0 . K_{-1}\cdots K_{-m}\) 的值是各位数码与位权乘积之和：

$$K_n r^n + K_{n-1} r^{n-1} + \cdots + K_0 r^0 + K_{-1} r^{-1} + \cdots + K_{-m} r^{-m} = \sum_{i=n}^{-m} K_i r^i$$

式中 \(r\) 是基数，\(K_i\) 是第 \(i\) 位的数码，取值范围为 \(0, 1, \cdots, r-1\)。

  • 二进制：基数为 2，数码为 0 和 1，计数「逢二进一」，第 \(i\) 位的位权为 \(2^i\)；
  • 八进制：基数为 8，数码为 0～7，计数「逢八进一」。由于 \(8 = 2^3\)，每 3 位二进制数恰好对应 1 位八进制数，两种进制可方便地互相转换；
  • 十六进制：基数为 16，数码为 0～9 和 A～F（A～F 分别代表 10～15），计数「逢十六进一」。由于 \(16 = 2^4\)，每 4 位二进制数对应 1 位十六进制数。

书写时常用后缀字母标识进制：B 表示二进制数，O 表示八进制数，D 表示十进制数（通常省略），H 表示十六进制数；此外也常用前缀 0x 表示十六进制数。

3. 二进制数转换为八进制、十六进制数

转换时以小数点为界分别处理：整数部分从小数点向左，每 3 位（八进制）或每 4 位（十六进制）分为一组，若最左侧不足 3 位或 4 位，则在高位补 0；小数部分从小数点向右同样每 3 位或 4 位分为一组，若最右侧不足，则在低位补 0。分组完成后，将每组直接替换为对应的八进制或十六进制数码即可。

【例 2.1】将二进制数 1111000010.01101 转换为八进制数和十六进制数。

解：转换为八进制时按 3 位分组——整数部分高位补 0 满足 3 位，得 001|111|000|010，即 1、7、0、2；小数部分低位补 0 满足 3 位，得 011|010，即 3、2：

$$\underbrace{001}_{1}\ \underbrace{111}_{7}\ \underbrace{000}_{0}\ \underbrace{010}_{2}\ .\ \underbrace{011}_{3}\ \underbrace{010}_{2} \Rightarrow (1702.32)_8$$

转换为十六进制时按 4 位分组——整数部分高位补 0 得 0011|1100|0010，即 3、C、2；小数部分低位补 0 得 0110|1000，即 6、8：

$$\underbrace{0011}_{3}\ \underbrace{1100}_{\mathrm{C}}\ \underbrace{0010}_{2}\ .\ \underbrace{0110}_{6}\ \underbrace{1000}_{8} \Rightarrow (3\mathrm{C}2.68)_{16}$$

反之，将八进制或十六进制数转换为二进制数，只需将每位数码分别替换为对应的 3 位或 4 位二进制数即可（必要时去掉整数最高位或小数最低位的 0）。通常先转换为二进制，再转为目标进制，这是最直接且不易出错的方式。

4. 任意进制数转换为十进制数

采用按权展开相加法：将各位数码与其对应位权（基数的幂次）相乘，再求和。例如 \((11011.1)_2 = 1 \times 2^4 + 1 \times 2^3 + 0 \times 2^2 + 1 \times 2^1 + 1 \times 2^0 + 1 \times 2^{-1} = 27.5\)。

5. 十进制数转换为任意进制数

对整数部分和小数部分分别处理：

  1. 整数部分使用除基取余法：不断除以目标进制的基数，记录余数，直至商为 0。最先得到的余数为最低位，最后得到的为最高位；
  2. 小数部分使用乘基取整法：不断乘以目标进制的基数，记录乘积的整数部分，直至小数部分为 0 或达到所需精度。最先得到的整数为最高位，最后得到的为最低位。

最终将两部分转换结果拼接，即得到目标进制数。

【例 2.2】将十进制数 123.6875 转换为二进制数。

解：整数部分（除 2 取余）：123 ÷ 2 = 61 余 1（最低位），61 ÷ 2 = 30 余 1，30 ÷ 2 = 15 余 0，15 ÷ 2 = 7 余 1，7 ÷ 2 = 3 余 1，3 ÷ 2 = 1 余 1，1 ÷ 2 = 0 余 1（最高位），故整数部分 \(123 = (1111011)_2\)。

小数部分（乘 2 取整）：0.6875 × 2 = 1.375，取整 1（最高位）；0.375 × 2 = 0.75，取整 0；0.75 × 2 = 1.5，取整 1；0.5 × 2 = 1.0，取整 1（最低位），故小数部分 \(0.6875 = (0.1011)_2\)。

所以，\(123.6875 = (1111011.1011)_2\)。

注意十进制小数与二进制小数（任意 \(r\) 进制小数）并非一一对应。一个十进制小数能精确转换为二进制小数，当且仅当它能表示成形如 \(k/2^n\) 的分数（\(k\)、\(n\) 为整数）。例如 \(0.3 = 3/10\)，分母 10 含因子 5，不是 2 的幂，因此无法用有限位二进制小数精确表示。反之，任何有限二进制小数都对应一个分母为 2 的幂的分数。这是浮点数运算产生舍入误差的根源，必须特别注意。

2.1.2定点数的编码表示

1. 真值与机器数

日常生活中用「+」「−」号表示正负（正号常省略），如 +15、−8，这类带符号的数称为真值。而计算机中表示的实际数值，数的符号与数值部分一同编码：通常用 0 表示正、1 表示负，这种符号数字化的表示形式称为机器数。例如机器数 0.101 表示真值 +0.101（这里的 0 仅用于分隔符号位与数值位）。

2. 机器数的定点表示

根据小数点位置是否固定，计算机中的数值分为定点表示和浮点表示（见 2.3 节）。定点表示用于表示定点小数和定点整数：

  • 定点小数：表示纯小数，约定小数点位于符号位之后、数值部分最高位之前；
  • 定点整数：表示纯整数，约定小数点位于数值部分最低位之后。

事实上，机器内部并无真实的小数点，只是人为约定了小数点的位置。因此，在定点数的编码和运算中，无须区分这两类数，只需关心符号位和数值位即可。定点数的编码表示主要有四种：原码、补码、反码和移码。

3. 原码、补码、反码、移码

（1）原码表示法

用机器数的最高位表示符号，其余各位表示数的绝对值。原码的定义如下（\(x\) 为真值，字长为 \(n+1\) 位）：

$$[x]_{原} = \begin{cases} 0,x, & 0 \le x < 2^n \\ 2^n - x = 2^n + |x|, & -2^n < x \le 0 \end{cases}$$

例如，若字长为 8 位，\(x_1 = +1110\)，\(x_2 = -1110\)，则其原码表示分别为 \([x_1]_{原} =\) 0,0001110；\([x_2]_{原} = 2^7 + 1110 =\) 1,0001110。

对于 \(n+1\) 位原码整数，其表示范围为 \(-(2^n-1) \le x \le 2^n-1\)（关于原点对称）。

注意零的原码表示有正零和负零两种形式：\([+0]_{原} =\) 0.0000000，\([-0]_{原} =\) 1.0000000。

原码表示的优点：① 与真值的对应关系简单直观，转换简便；② 用原码实现乘除运算比较简便。缺点：① 表示不唯一，存在 ±0 两种编码；② 用原码实现加减运算比较复杂。

（2）补码表示法

补码表示法的加减运算均可通过加法器实现。正数的补码与原码相同，负数的补码等于模（\(n+1\) 位）与 \(|x|\) 之差。补码的定义为：

$$[x]_{补} = \begin{cases} 0,x, & 0 \le x < 2^n \\ 2^{n+1} + x = 2^{n+1} - |x|, & -2^n \le x < 0 \end{cases} \pmod{2^{n+1}}$$

等价地，无论正负，均有 \([x]_{补} = 2^{n+1} + x \ (-2^n \le x < 2^n,\ \bmod\ 2^{n+1})\)。

例如，若字长为 8 位，\(x = +1010\)，则 \([x]_{补} =\) 0,0001010；\(x = -1010\)，则 \([x]_{补} = 2^8 - 1010 =\) 1,1110110。

考点补码的表示范围（2010、2014、2022 真题）。对于 \(n+1\) 位补码整数，表示范围为 \(-2^n \le x \le 2^n - 1\)，比原码多表示一个负数，即 \(-2^n\)。几个特殊值的补码（\(n+1\) 位）：
  • \([+0]_{补} = [-0]_{补} = 0.00\cdots 0\)（全 0），零的补码表示是唯一的；
  • \([-1]_{补} = 2^{n+1} - 1 = 1.11\cdots 1\)（全 1）；
  • 最大正整数：\([2^n - 1]_{补} = 0\,11\cdots 1\)（符号位 0，数值位全 1）；
  • 最小负整数：\([-2^n]_{补} = 1\,00\cdots 0\)（符号位 1，数值位全 0）。

模运算（了解）：一个数与它除以「模」后得到的余数是等价的。设 \(A = B + K \times M\)（\(K\) 为整数），记为 \(A \equiv B \pmod M\)，则 \(B\) 是 \(A\) 除以 \(M\) 的余数。在补码运算中，\(A \equiv B \pmod M\) 时 \([A]_{补} = [B]_{补}\)；特别地，\([-B]_{补} = M - |B| \pmod M\)，故减去一个数等价于加上它的补数——补码正是借助加法运算实现减法运算，这是补码设计的核心思想。

（3）补码与真值的相互转换
考点补码和真值的互转（2020、2023 真题）。真值 → 补码：对于负数，符号位取 1，其余各位由其绝对值按位取反、末位加 1 得到；正数直接照写（与原码相同）。补码 → 真值：若符号位为 0，直接读作正数；若符号位为 1，真值为负数，其绝对值由补码的数值部分按位取反、末位加 1 得到。
（4）变形补码（双符号位补码）

为便于溢出检测，可采用双符号位的补码表示（又称变形补码）。双符号位 00 表示正数、11 表示负数。若总位数为 \(n+2\)（高位为符号位，其余为数值位），则变形补码定义为：

$$[x]_{变形补} = \begin{cases} 00,x, & 0 \le x < 2^n \\ 2^{n+2} + x = 2^{n+2} - |x|, & -2^n \le x < 0 \end{cases} \pmod{2^{n+2}}$$

双符号位中的高位符号位在判断「溢出」中发挥作用（详见 2.2.3 节）。

（5）反码表示法（了解即可）

反码可视为从原码转换为补码的中间表示形式。正数的反码与原码相同；负数的反码由其原码的数值部分按位取反（末位不加 1）得到。反码存在明显不足：① 零的表示不唯一（存在两种编码）；② 表示范围比相同字长的补码少一个最小负数（\(-2^n\)）。因此，反码在计算机中很少使用。

（6）移码表示法

移码主要用于表示浮点数的阶码，其核心思想是将真值 \(x\) 加上一个固定常量（偏置值），实现整数整体右移。设字长为 \(n+1\) 位，偏置值取 \(2^n\)，则移码定义为：

$$[x]_{移} = 2^n + x, \quad -2^n \le x < 2^n$$

例如，若字长为 8 位，偏置值为 \(2^7\)，\(x = +10101\)，则 \([x]_{移} = 2^7 + 10101 =\) 1,0010101；\(x = -10101\)，则 \([x]_{移} = 2^7 - 10101 =\) 0,1101011。

注意在 IEEE 754 标准的浮点数中，\(k\) 位阶码的偏置值取 \(2^{k-1} - 1\)，如 8 位阶码的偏置值为 127（详见 2.3.1 节），与上式中的 \(2^n\) 不同。

移码（设字长 \(n+1\)，偏置值 \(2^n\)）的主要特点如下：

  1. 零的表示唯一：\([+0]_{移} = [-0]_{移} = 2^n = 1\,00\cdots 0\)（\(n\) 个 0）；
  2. 在相同字长时，移码与补码的数值位完全相同，仅符号位相反（将补码的最高位取反即得移码）；
  3. 移码全 0 时，对应真值的最小值 \(-2^n\)；移码全 1 时，对应真值的最大值 \(2^n - 1\)；
  4. 移码保持真值的大小顺序：移码值越大，对应真值越大，便于阶码比较。

4. 四种编码表示的总结与对比

考点各种码制的特点（2015 真题）。① 正数的原码、反码、补码相同，移码则不同；② 原码与反码在数轴上关于原点对称，二者都存在 +0 与 −0 两种表示；③ 补码与移码的表示不对称，零的表示唯一，且比原码和反码多表示一个负数（\(-2^n\)）；④ 原码表示直观（但乘除运算简便），而负数的补码和反码不能像原码那样直观判断大小，不过在同为负数的前提下，补码或反码的数值部分越大，其真值也越大。

下表给出相同位数下四种编码的整数表示范围对比（设含 1 位符号位、共 \(m\) 位）：

编码方式表示范围（\(m\) 位整数）零的表示对称性
原码\(-(2^{m-1}-1) \sim 2^{m-1}-1\)±0 两种关于原点对称
反码\(-(2^{m-1}-1) \sim 2^{m-1}-1\)±0 两种关于原点对称
补码\(-2^{m-1} \sim 2^{m-1}-1\)唯一（全 0）不对称，多一个最小负数
移码\(-2^{m-1} \sim 2^{m-1}-1\)唯一（\(10\cdots0\)）不对称，保持大小顺序

2.1.3整数的表示

1. 无符号整数的表示

当所有二进制位均用于表示数值（无符号位）时，该编码称为无符号整数，简称无符号数。此时数值隐含为非负整数，由于无须保留符号位，在相同字长下，无符号整数能表示的最大值大于有符号整数。例如，无符号整数可用于地址等非负场景，或用于确定不会产生负值的加减运算场景。

例如，8 位无符号整数的最小值为 0000 0000（0），最大值为 1111 1111（\(2^8-1 = 255\)），表示范围为 0～255；而 8 位有符号数（补码表示）的最小值为 1000 0000（\(-2^7 = -128\)），最大值为 0111 1111（\(2^7-1 = 127\)），表示范围为 −128～127。

2. 有符号整数的表示

有符号整数通过在数值位前增设一位符号位（0 表示正、1 表示负）来表示正负。虽然原码、反码和补码均可用于表示有符号整数，但现代计算机统一采用补码，因其具有以下优势：

  1. 零的表示唯一（无 +0 与 −0 之分）；
  2. 符号位与数值位一同参与运算，使加减法统一为加法操作；
  3. 表示范围更大：比原码和反码多表示一个最小负数。

因此，\(n\) 位有符号整数（补码）的表示范围为 \(-2^{n-1} \sim 2^{n-1}-1\)。

2.1.4C 语言中的整数类型及类型转换

1. C 语言中的整型数据类型

考点int 数据的表示范围（2017、2019、2024 真题）。

C 语言提供了多种整型类型，具体长度依赖于编译器和目标平台。常见情况如下：

  • 短整型：short（或 short int），通常为 16 位；
  • 整型：int，通常为 32 位；
  • 长整型：long（或 long int），在 32 位系统中为 32 位，在 64 位系统中通常为 64 位；
  • 在上述类型前加 unsigned 关键字，可定义对应的无符号类型（如 unsigned int、unsigned short 等）；若未显式指定 signed 或 unsigned，则默认为有符号类型；
  • 字符型：char，通常为 8 位，是一种特殊的整数，通常可按无符号数解释。

在现代系统中，所有有符号整数均以补码形式存储；无符号类型则将全部位用于表示非负数值。

2. 整型数据的类型转换

定点数在类型转换过程中，若涉及字长变化，则会触发两种基本操作：位截断与位扩展。

1）位截断：当长类型转换为短类型时，系统直接丢弃高位，仅保留低位部分。由于目标类型的表示范围较小，故可能会导致数值发生变化，且具有较强的隐蔽性（编译器通常不会报错或警告）。

2）位扩展：当短类型转换为长类型时，系统通过填充高位来保持数值语义不变。具体扩展的方式取决于源数据的符号性：

  • 零扩展：用于无符号数，在高位补 0；
  • 符号扩展：用于补码表示的有符号数，高位重复填充符号位。

C 语言支持通过强制类型转换实现不同类型间的转换，其语法为 TYPE b = (TYPE) a;，转换结果是一个 TYPE 类型的值。根据源类型与目标类型的字长和符号性，可分为三种情形。

3. 整型类型的三种相互转换

考点整型类型的相互转换（2011、2016、2019、2024 真题）。
（1）长类型转换为短类型：位截断

转换规则：保留低位，丢弃高位。考虑如下代码片段（int 型为 32 位，short 型为 16 位）：

int x=165537, u=-34991;
short y=(short)x, v=(short)u;
printf("x=%d, y=%d\n", x, y);
printf("u=%d, v=%d\n", u, v);

运行结果：

x=165537, y=-31071
u=-34991, v=30545

其中 x、y、u、v 的十六进制表示分别为 0x000286A1、0x86A1、0xFFFF7751、0x7751。可见，当长类型转换为短类型时，系统直接截断高位、仅保留低位部分。由于目标类型的数值范围较小，这种位截断可能导致结果与原值在语义上不一致：由于 165537 超出了 16 位有符号整数的最大值 32767，截断后的低 16 位被解释为 −31071；而 −34991 的低 16 位 0111 0111 0101 0001（0x7751）的最高位为 0，被重新解释为正数 30545。此类转换不会触发任何异常或错误报告，具有很强的隐蔽性。

（2）相同字长的转换：仅改变解释方式

转换规则：位模式保持不变，仅重新解释其含义。考虑如下代码片段：

short x=-4321;
unsigned short y=(unsigned short)x;
printf("%d, %u\n", x, y);

运行结果：

x=-4321, y=61215

有符号数为负数时，无符号数只能表示非负数。从输出结果看，y 的值似乎与 x 毫无关联；但将二者转换为二进制形式后（见下表），可观察到：short 型强制转换为 unsigned short 型后，所有二进制位均保持不变，x 按补码规则解释、y 则按无符号规则解读。

变量值二进制位
x−43211110111100011111
y612151110111100011111

这表明：相同长度的整型类型转换不改变位模式，仅改变对这些位的解释方式。

（3）短类型转换为长类型：位扩展

转换规则：若源数据为有符号数，则执行符号扩展；若源数据为无符号数，则执行零扩展。扩展后数值语义保持不变，例如 16 位补码 1 000 0000 0000 0000（−32768）符号扩展为 32 位后仍为 −32768。

易混三种转换的后果要分清：位扩展不改变数值（补 0 或补符号位都是「扩写」）；相同字长互转不改变位模式、只改变解释（值可能变化）；位截断直接丢弃高位（值大概率变化，且无警告）。
