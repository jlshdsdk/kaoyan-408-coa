    第7章 输入/输出系统

    本章的主角是「主机与外设如何配合」：I/O 接口是主机与外设之间的交接界面，而 I/O 方式决定了 CPU 要以多大的代价完成数据传送。I/O 方式是本章的重点和难点，历年不但以选择题形式考查基本概念和原理，还可能以综合题形式考查各种 I/O 方式的效率计算——特别是程序查询方式的时间开销、中断方式的各种原理、特点与处理过程、中断屏蔽与多重中断、DMA 方式的特点与传送过程，以及 DMA 与中断方式的区别。学接口部分时抓住「功能—结构—类型—编址」这条线，学 I/O 方式时抓住「CPU 被打扰的程度越来越小」这条主线：查询（CPU 全程盯着）→ 中断（准备阶段并行、传送靠 CPU）→ DMA（传送也交给硬件）。

    408考纲要求
    • （一）I/O 接口（I/O 控制器）：I/O 接口的功能和基本结构；I/O 端口及其编址。
    • （二）I/O 方式：
      • 程序查询方式；
      • 程序中断方式：中断的基本概念；中断响应过程；中断处理过程；多重中断和中断屏蔽的概念；
      • DMA 方式：DMA 控制器的组成；DMA 传送过程。

    本章小结

    下表整理自教材本章小结，回答开篇的两个思考题。

    问题结论要点
    I/O 设备有哪些编址方式？各有何特点？ I/O 设备的编址方式主要有统一编址和独立编址。统一编址是指将主存地址空间的一部分分配给 I/O 端口，可使用普通的访存指令直接访问 I/O 设备，编程简单；但会占用主存地址空间，减少可用主存容量。独立编址是指 I/O 端口地址空间与主存地址空间相互独立，I/O 端口不占用主存资源；但访问 I/O 设备需使用专用 I/O 指令（如 IN、OUT），增加了指令集的复杂性。
    CPU 响应中断需要哪些条件？ ① CPU 内部的中断允许触发器（开中断状态）处于开放状态；② 外设发出中断请求，且其接口中的中断请求触发器置为「1」，以维持中断请求信号；③ 外设接口中的中断允许触发器为「1」，才能将中断请求送达 CPU。当上述三个条件同时满足时，CPU 在当前指令执行结束后响应中断。

    常见问题和易混淆知识点

    问题 1在开中断情况下，CPU 检测到中断就一定会立即响应吗？

    是的。在开中断状态下，CPU 总在每条指令执行结束时采样中断请求，一旦检测到中断请求，即表明该请求未被屏蔽且有效，CPU 必定会立即响应。

    需要说明的是：在单重中断系统中，进入中断服务程序后会自动关中断，此后即使有新的中断请求也无法被检测——但这与「开中断时检测到必响应」并不矛盾，因为前提（开中断）已被破坏；而在多重中断系统中，未被屏蔽的高优先级中断可以在低优先级中断服务程序执行期间被检测并响应。

    易混「检测不到」与「不响应」别搅在一起：关中断/被屏蔽 → 请求根本进不了判定环节；开中断且有有效请求 → 指令一执行完必响应。判断题说「开中断时 CPU 检测到中断请求却不予响应」必错；说「关中断后新请求无法被检测」则对。

    问题 2向量中断、中断向量、向量地址三个概念是什么关系？

    中断向量：指中断服务程序的入口地址。每个中断源对应一个唯一的中断服务程序，其入口地址即为该中断源的中断向量。系统通常将所有中断向量集中组织成一张中断向量表；也有系统在中断向量表中存放转向服务程序的转移指令（构成转移表）。

    向量地址：指中断向量表（或转移表）中某一项的存储地址，即中断向量所在的内存单元地址。它通常由中断类型号（也称中断号）乘以表项长度计算得出，例如表项占 4 字节、中断类型号为 5，则向量地址为 \(5 \times 4 = 20\)（假设从 0 开始）。因此向量地址是 CPU 用于在中断向量表中定位中断向量的「索引位置」。

    当向量中断发生时，中断源（或中断控制器）向 CPU 提供中断类型号，CPU 据此生成向量地址，并从向量表中取出对应的中断向量（入口地址），直接转去执行相应的中断服务程序。

    易混三者链条记牢：中断类型号（编号）→ 向量地址（表中的位置 = 类型号 × 表项长度）→ 中断向量（表里存的内容 = 服务程序入口地址）。类型号是 CPU 从数据总线上拿到的，向量表在主存中，别把「向量」当成「地址」的同义词再反着用一遍。

    问题 3程序中断和调用子程序有何区别？

    虽然程序中断和子程序调用都引起程序执行流程的转移，但二者在本质上存在显著差异，主要体现在四个方面：

    1. 触发时机：子程序调用由程序员通过 CALL 指令主动发起，发生时刻和位置是确定的；而中断由外部设备或内部事件随机触发，CPU 只在每条指令执行结束时采样中断请求，一旦条件满足便转入中断处理，具有明显的异步性和不可预测性。
    2. 服务关系：子程序调用完全为主程序服务，二者构成主从关系——主程序在需要时调用子程序，执行完毕后返回主程序继续运行；中断服务程序通常与主程序无直接关联，是为响应外部事件（如数据到达、定时器溢出等）而执行的独立任务，二者属于平行关系。
    3. 实现机制：子程序调用是纯软件行为，返回地址的保存无须专门硬件即可完成；而中断处理依赖软硬件协作，需借助中断请求线、中断控制器和优先级判优电路等硬件，才能完成中断请求的接收、判优、响应和断点保护等操作。
    4. 嵌套级别：子程序可多层嵌套，嵌套深度主要受限于系统栈空间；中断嵌套则受优先级机制约束——只有更高优先级的中断才能打断当前正在执行的中断服务程序。出于硬件复杂性和实时性考虑，实际系统中中断优先级通常较少，嵌套层次有限。
